# pgchroma Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stateless server that speaks Chroma's v2 HTTP API and stores data in Postgres + pgvector, plus a verified migration command from Chroma (Cloud or self-hosted).

**Architecture:** Starlette app → `Store` (async psycopg pool) → one Postgres schema holding catalog tables and one table per collection. Filters compile to parameterized SQL. A differential test suite drives the official `chromadb` client against real Chroma and pgchroma and compares results.

**Tech Stack:** Python 3.10+, starlette, uvicorn, psycopg 3 + psycopg_pool, pgvector (python), orjson, numpy, httpx, rich; pytest, pgserver (embedded Postgres for local tests), chromadb 1.5.9 (tests only).

**Spec:** `docs/superpowers/specs/2026-10-25-pgchroma-design.md`

## Global Constraints

- Postgres 14+, pgvector 0.5+; use iterative index scans only when pgvector >= 0.8.
- Python >= 3.10. License MIT.
- Runtime deps limited to: starlette, uvicorn, psycopg[binary,pool], pgvector, orjson, numpy, httpx, rich.
- Error bodies are `{"error": "<Name>", "message": "..."}` with Chroma's status codes.
- Default tenant `default_tenant`, default database `default_database` with id `00000000-0000-0000-0000-000000000000`.
- Distances: l2 = squared Euclidean, cosine = 1 - cos, ip = 1 - dot.
- `pre-flight-checks` returns `{"max_batch_size": 5461, "supports_base64_encoding": true}` (batch size configurable).
- All SQL identifiers built from internal UUIDs only; all user values are bind parameters.

## Review Focus

1. Metadata int vs float vs bool: `{"n": 1}` must not match `{"n": true}`; `1` and `1.0` behavior must equal Chroma's — differential test `test_where_number_types` (Task 6).
2. Unicode / quotes / `%` / `_` / backslashes in document `$contains` and in ids — differential test `test_document_contains_special_chars` (Task 6).
3. Very large batch (5461 records × 384 dims, base64) — integration test `test_add_max_batch` (Task 3).
4. Query on an empty collection and with `n_results` > count — differential test `test_query_empty_and_overflow` (Task 6).
5. Two pgchroma processes creating the same collection / first-write dimension race — integration test `test_concurrent_first_write` (Task 3).

### Task 2: Filter compiler

**Files:** Create `src/pgchroma/filters.py`, `tests/test_filters.py`

**Interfaces:**
- Produces: `compile_where(where: dict | None) -> tuple[str, list]` and `compile_where_document(wd: dict | None) -> tuple[str, list]`; both return a SQL boolean expression over columns `metadata` / `document` with `%s` placeholders, `("TRUE", [])` for None. Raise `InvalidArgumentError` (Task 4 errors module; define the class here first if Task 4 not done — it lives in `src/pgchroma/errors.py`) on malformed filters with Chroma-like messages.

- [ ] Tests (SQL executed against Postgres on a temp table with fixed rows): `$eq/$ne/$gt/$gte/$lt/$lte/$in/$nin`, `$and/$or`, implicit eq, missing-key semantics (`$ne`/`$nin` match missing), bool vs number separation, list-valued metadata with `$contains/$not_contains`, document `$contains/$not_contains/$regex/$not_regex` with `%`, `_`, `\`, quotes, unicode.
- [ ] Implement with `jsonb_typeof` guards: numbers via `(metadata->>k)::double precision`, strings via `metadata->>k`, bools via `metadata->k = 'true'::jsonb`; `$contains` on documents via `strpos(document, %s) > 0`.
- [ ] Run → PASS; commit.

### Task 3: Store — catalog and records

**Files:** Create `src/pgchroma/errors.py`, `src/pgchroma/store.py`, `src/pgchroma/config.py` (collection configuration + schema defaults), `src/pgchroma/vectors.py`, `tests/test_store.py`

**Interfaces:**
- Produces `class Store` with async methods (all take `tenant: str, database: str` where relevant):
  `create_tenant(name)`, `get_tenant(name) -> dict`, `update_tenant(name, resource_name)`, `create_database(tenant, name)`, `get_database(tenant, name) -> dict`, `list_databases(tenant, limit, offset) -> list[dict]`, `delete_database(tenant, name)`,
  `create_collection(tenant, database, name, metadata, configuration, schema, get_or_create) -> dict`, `get_collection(tenant, database, name_or_id) -> dict`, `list_collections(tenant, database, limit, offset) -> list[dict]`, `count_collections(tenant, database) -> int`, `update_collection(tenant, database, id, new_name, new_metadata, new_configuration)`, `delete_collection(tenant, database, name)`, `fork_collection(tenant, database, id, new_name) -> dict`,
  `add(coll: dict, ids, embeddings: np.ndarray|None, metadatas, documents, uris)`, `upsert(...)`, `update(...)`, `delete(coll, ids, where, where_document, limit) -> int`, `count(coll) -> int`,
  `get(coll, ids, where, where_document, limit, offset, include) -> dict`, `query(coll, query_embeddings: np.ndarray, n_results, ids, where, where_document, include) -> dict`.
  Collection dicts are already in Chroma's JSON shape (`id, name, configuration_json, schema, metadata, dimension, tenant, database, log_position, version`).
- `vectors.decode_embeddings(items: list) -> np.ndarray | None` accepts float lists or base64 strings.
- Errors: `ChromaError(status=500)`, `NotFoundError(404)`, `InvalidArgumentError(400)`, `UniqueConstraintError` mapped to `{"error":"ChromaError"}` with 409 for duplicate collection (observed), `AuthError(401)`.

- [ ] Tests: add/get round-trip incl. metadata types; duplicate add ignored; update merge + null delete; upsert keeps order; delete by where returns count; dimension mismatch message; `test_add_max_batch`; `test_concurrent_first_write` (two pools, same collection, parallel adds with same dim → no error, count correct).
